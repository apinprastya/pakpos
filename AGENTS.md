# AGENTS.md

Guidance for AI coding agents working on **Pakpos**, a desktop REST API client (a Postman-style tool, REST only) built with Go + Wails v3 and React/TypeScript.

Read before larger changes:
- `docs/ARCHITECTURE.md`: decisions and layering
- `docs/ROADMAP.md`: feature tiers (Tiers 1–3 done in code; Tier 3's release run and smoke tests are left)
- `docs/PLAN-TIER3.md`: the latest plan: Decisions (including those made per milestone), Progress, carry-overs and "Definition of Done — what's left"
- `docs/PLAN-TIER2.md`: the previous plan, for the reasoning behind Tier 2 decisions
- `docs/SMOKE-TEST.md`: the manual release checklist

## Stack

- **Backend:** Go 1.26, Wails v3.0.0 (`github.com/wailsapp/wails/v3`), module name `pakpos`
- **Frontend:** React 19, TypeScript 6, Vite 8, Tailwind CSS v4, shadcn/ui (`radix-nova` style), Zustand, lucide-react, sonner, CodeMirror 6, dnd-kit, cmdk (command palette)
- **Storage:** YAML workspace files with ULID IDs (`gopkg.in/yaml.v3`, `oklog/ulid`), `fsnotify` watcher, `modernc.org/sqlite` (pure Go, no CGO)
- **Secrets:** `zalando/go-keyring` (OS keychain), with an encrypted-file fallback (`golang.org/x/crypto`: Argon2id + AES-256-GCM)
- **HTTP:** `net/http`; `andybalholm/brotli` (pure Go) decodes `br` responses; `software.sslmate.com/src/go-pkcs12` (BSD-3, pure Go) reads PKCS#12 client certificates
- **Scripting:** `github.com/dop251/goja` (MIT, pure Go; pinned to a commit, it has no tags), which brings `dlclark/regexp2/v2`, `go-sourcemap/sourcemap`, `google/pprof` and `golang.org/x/text`
- **Targets:** Linux (WebKitGTK), macOS, Windows

## Commands

Run from the repo root. `wails3 task` is the bundled Task runner, so no separate `task` install is needed.

| Command | Purpose |
|---|---|
| `wails3 dev` | Run the app with hot reload |
| `wails3 build` | Production build to `bin/pakpos`. Also generates TS bindings. |
| `wails3 task test` | Go and frontend tests |
| `wails3 task coverage` | Tests with coverage gates. **Must pass (≥ 80%).** |
| `wails3 task lint` | gofmt, go vet, golangci-lint (installed binary, or the pinned v2.15.0 via `go run`), tsc, ESLint, Prettier |
| `wails3 task version` | Prints the version builds are stamped with (CalVer from `git describe`, or `PAKPOS_VERSION`) |
| `wails3 task package:linux` / `package:windows` / `package:darwin` | Packages for that OS into `bin/` (see README "Building packages") |
| `wails3 task release:next` | Next CalVer release number for this month (from local tags) |
| `wails3 generate bindings -ts` | Regenerate `frontend/bindings` after changing bound Go services |

Frontend only (run in `frontend/`): `npm test`, `npm run coverage`, `npm run typecheck`, `npm run lint`, `npm run format`.

Before you finish a task, run `wails3 task lint` and `wails3 task coverage`, and make sure both pass.

## Architecture rules

- **Packages under `internal/core` and `internal/store` must never import Wails.** Wails code lives only in `main.go` and `internal/service`. This keeps the core unit-testable and leaves room for a headless CLI runner later.
- **Services are thin.** They translate between Wails and core packages and contain no business logic.
- **HTTP requests are always sent from Go (`net/http`), never from the webview.** This avoids CORS and gives full control over TLS, proxies and cookies.
- **Workspace data is plain files, one request per YAML file**, so diffs stay small for git. History and app state go in SQLite.
- **Secrets never go into workspace files or SQLite.** Files store the key with `secret: true`; the value lives in the OS keychain, or in `<data>/secrets.enc` (encrypted with a master password) when there is no keychain. History stores requests as written (`{{vars}}` unresolved).
- **Prefer pure-Go dependencies (no CGO)** so cross-compilation stays simple.
- **Keep the planned Tier 2 fields** (`auth.type: inherit`, `seq`, variable scopes) in models even before they are used. This avoids a file format migration later.

## Go conventions

- Code must be `gofmt`-clean and pass `go vet`. Use table-driven tests.
- Use `httptest.Server` for HTTP tests (`internal/testnet` for TLS servers with a test CA, mTLS and a forwarding proxy), `t.TempDir()` for filesystem tests, in-memory SQLite for store tests, and fakes behind interfaces (keychain, clock).
- Return errors with context (`fmt.Errorf("open workspace %q: %w", path, err)`). Do not panic in library code.
- Pass `context.Context` through anything that does I/O or can be cancelled.
- Bound service methods should use JSON-tagged DTO structs so the generated TS types stay clean.
- **Services never import Wails.** Anything that needs the Wails app (dialogs, events) goes behind an interface in `internal/service/core.go` and is implemented in `wails_adapters.go`. Tests use fakes.
- New typed events: add a const and a payload struct in `internal/service`, then `application.RegisterEvent[T](name)` in `main.go`'s `init`, so the bindings are typed.
- **Database changes go in a new migration file**, `internal/store/sqlite/migrations/NNNN_name.sql`. Never edit an applied migration.
- `RequestService.Send(ctx, sendId, req, parentId)` records history against the workspace that was open when the send **started**, so switching workspaces mid-send doesn't misfile it. `parentId` lets an unsaved draft inherit from its collection or folder.
- **Send pipeline** (`internal/pipeline`): services call `Session.Prepare` / `PrepareCode` / `Preview` / `VisibleVariables` and never resolve variables themselves. `Preview.overridden` lists inherited headers the request's own enabled headers replace (`inherit.Result.Overridden`; the Headers view strikes them through); `Visible.shadowed` lists the definitions that lose to a higher scope (highest first per key), which `overlayDraft` uses when a settings tab removes a row. Scopes are passed lowest precedence first (globals, collection, environment, local). A secret without a usable value still shadows lower scopes and stays unresolved. Values are resolved as plain text and encoded where they land: in a raw JSON body a value inside a string literal is JSON-escaped (`vars.ResolveJSON`; outside quotes it goes in as is, so `{{count}}` can be a number); query rows, path params and urlencoded fields are URL-encoded by `httpexec` at send time. `pipeline.EncodedForms` lists those encoded forms so masking still finds secrets.
- **Secrets:**
  - Keys are `pakpos/<workspaceId>/<scopeId>/<key>` (scope IDs, so renames don't orphan values). Bookkeeping (cleanup on delete, copy on duplicate, rename pairs `{from, to}` passed with the save) lives in `pipeline`, not in services.
  - `EnvService.RevealSecret` and `MakeVariablePlain` are the only ways a value leaves the store; everything else returns a `set` flag.
  - New master passwords go through `secrets.CheckNewPassword` (8 characters); user-facing store errors through `secrets.Explain`.
  - **Secret index** (`0004_secret_index.sql`): `Core.session` calls `pipeline.Session.WithSecretIndex(c.db)`, which wraps the store so every write records its key and every delete forgets it (key names only, never values). Don't write to the store around the session, or the key won't be indexed. `Session.PruneSecrets(c.started)` runs after a workspace opens and after `EnvService.Unlock` (`Core.pruneSecrets`; failures logged): it deletes indexed keys whose scope or secret variable is gone, skips keys written since the app started (unsaved rows) and workspaces with load problems, and adopts the keys of current secret variables first. Tests that need a prune "on the next start" set `h.core.started` ahead (see `harness.restart` in `e2e_test.go`).
  - Real-keychain tests run only with `PAKPOS_TEST_KEYRING=1`. Services take `Config.Secrets`; tests use `newHarness` (`secrets.Fake`) or `newHarnessWith` (e.g. a real `FileStore` in a temp dir).
- **Window and UI state:** the window's normal bounds plus maximised/fullscreen live in the settings table under `windowstate.Key` (saved 500 ms after changes settle and on close; never restored minimised; the position is applied on first show only if still on a screen, and Wayland ignores it). App-wide UI state (panel layouts, column splits) is the `ui_state` table via `UIStateService` (JSON values, validated).
- **macOS window:** no title bar (`MacTitleBarHidden` in `main.go`). `markPlatform` sets `data-platform="mac"` on `<html>`; the `mac:` Tailwind variant and `TitleBarSpace` reserve the top-left 80×40 px for the window buttons (rail cell + sidebar cell). `.window-drag` makes an element's own empty area drag the window on macOS only (its descendants are `no-drag`); the tab bar uses it. Keep the header row 40 px and the reserved width if you change the rail or sidebar.
- History is per workspace (list, clear and retention). The selected environment lives in SQLite `workspace_state`, never in the workspace.
- **Debug hops:** `httpexec.WithRecorder(ctx, rec)` makes `Execute` record each wire exchange (`model.Hop`: headers as written via `httptrace.WroteHeaderField`, the first `model.MaxHopBody` of the body, connection, status and raw response headers). `RequestService.Send` masks them with `pipeline.MaskHops(hops, Session.SendSecrets(...))`, which writes secrets as `[secret:name]` (`pipeline.SecretMark`), never `{{name}}`: in a hop, `{{name}}` means unresolved and returns them in `SendResult.Hops`. They hold no secret values but are still never stored in history; the response pane's Debug tab (`DebugView`, `debugText`) shows them.
- **Per-request settings:** `model.Request.Settings` (`timeoutMs`, `followRedirects`, `maxRedirects`, `verifyTls`, pointers; nil = the app setting; omitted from YAML when unset). Writing a request with any of them is a v3-only write (`upgradeForRequestLocked` → `upgradeManifestLocked(FormatVersion)`). `httpexec.Execute` applies them per send without rebuilding the client: a context timeout, and a `sendOptions` value in the context that `CheckRedirect` and the router read. Limits are `httpexec.MaxTimeoutMs`/`MaxRedirectsCap` (`settings` re-exports them); `ValidateRequestSettings` runs on send and in `RequestService.Save`/`SaveAs`. The frontend's "Settings" request tab (`features/request/SettingsSection.tsx`, helpers in `requestSettings.ts`) keeps the same limits. cURL: `-k`, `-L`/`--location-trusted`, `--max-redirs`, `-m/--max-time` import into the settings (others stay warnings), and `curl.Generate` writes them back; other codegen languages ignore them.
- **Network (proxy, CA, client certificates):** app settings `proxy {mode: none|system|custom, url, username, bypass}`, `caFile`, `clientCerts [{id, host, certFile, keyFile, pfxFile}]`; `settings.Normalize` gives new certificates an id, `settings.Network()` maps them to `httpexec.Network`. "system" is Go's `ProxyFromEnvironment` (env vars only, read once per process). Bypass and certificate hosts use `httpexec.MatchHost` (`*`, `*.x`, `.x`, CIDR, exact). Passwords never go into SQLite: the proxy password is `pakpos/_app/proxy` and a PKCS#12 passphrase `pakpos/_app/cert/<id>` (`secrets.AppKey`, `httpexec.SecretProxy`/`CertSecret`), read lazily through `Network.Secret` (`Core.appSecret`; not found or no master password = ""). `SettingsService.SetProxyPassword`/`SetCertPassphrase` ("" deletes) and `NetworkSecretStatus` (a `locked` flag, never values); removing a certificate deletes its passphrase. `SettingsService.Set` loads a new or changed CA file / PEM pair first (`Network.Check`) so a bad path fails the save, not the next send. Proxy failures are `KindProxy`; CA and certificate problems `KindTLS` with a message naming the file; a locked store sets `SendResult.SecretsLocked`.
- **Transport cache:** `httpexec.Transports` (one per `Core`, shared by every executor) holds one `*http.Transport` per (network config, insecure, client certificate). `routeTransport` picks it per hop (redirects included) from the send's options and the hop's host, under `recordingTransport`, so debug hops work for every transport. A different network config evicts stale transports; `Transports.Reset` (on network setting or password changes) closes idle connections. A per-request `verifyTls` therefore never drops other sends' pooled connections.
- **Cookies:** `core/cookies.Jar` is the app's own `http.CookieJar` (RFC 6265 domain/path rules, public suffix list from `x/net/publicsuffix`); `net/http/cookiejar` can't list cookies, so it isn't wrapped. Persistent cookies (Max-Age/Expires) are written through `cookies.Store` = `sqlite.Store.Cookies(workspaceID)` (`0005_cookies.sql`; workspace `""` holds sends without a workspace); session cookies stay in memory. Expired rows are pruned when a jar loads. `Core.loadJarLocked` switches jars on workspace open/close. `CookieService` (thin: List/Add/Update(old ref, cookie)/Delete/ClearDomain/ClearAll) turns `cookies.ErrInvalid`/`ErrNotFound` into user sentences. Cookies never go into workspace files.
- **Other auth** (Tier 3 M7; settings blocks `Auth.Digest/AWSV4/JWT/Hawk/NTLM`, omitempty, `Auth.IsV3`): `auth.Apply` signs JWT, AWS SigV4 and Hawk last in `Build` (the body is buffered for payload hashes; `auth.Now`/`Random` are test hooks); Digest and NTLM are handshakes in `httpexec.send` (`handshake.go`: Digest retries once on a 401 from the same URL by rebuilding the request; NTLM uses a per-send `dedicated` transport, HTTP/1.1, one connection per host, never the `Transports` cache). A user `Authorization` header wins. Signing errors are `KindAuth` ("Check the Auth tab"; the response pane offers "Open the Auth tab"). `pipeline.AuthSecrets` adds the resolved secret fields to every send's masks. Code: `auth.MaterializeWith(req, keep)`, where `keep` lists the types a language writes itself (`curl.Keeps`: basic, Digest, NTLM, SigV4; Python Digest; PHP Digest, NTLM); computed SigV4/JWT/Hawk headers need resolved values and come with an expiry warning. Frontend: `features/request/OtherAuthFields.tsx` is a lazy chunk (`otherAuthLazy.tsx`, `loadOtherAuth`); blocks come from `AUTH_BLOCKS` in `lib/model.ts`, secret fields map through `BLOCK_FIELDS` in `auth.ts`.
- **httpexec** sets `Accept-Encoding: gzip, deflate, br` (`httpexec.AcceptEncoding`) unless the user set one, and decodes the body itself (`decodedBody`); a body that doesn't match its coding is `KindDecode`. Keep `features/request/autoHeaders.ts` in step with the headers `Build` adds (`model.Body.DefaultContentType` is shared with codegen).
- **OAuth 2.0** (`core/auth/oauth2`, stdlib only, no `x/oauth2`): `model.Auth.OAuth2` (`*model.OAuth2`, omitempty; type `oauth2`; writing it is a v3-only write via `Auth.IsV3()`). Every string field resolves `{{vars}}` (`vars.ResolveRequest`); client secret and password follow the secret auth field rule (`SecretField` `oauth2ClientSecret`/`oauth2Password`, `secretFieldValue`/`withSecretField`). Tokens are stored as JSON in the secret store under `pakpos/<ws>/<ownerId>/{oauth2}` (`pipeline.OAuth2TokenKey`; owner = request, folder or collection whose auth got it; `pipeline.TokenOwner(eff)`), written through the session so the index records them. `Session.Token` (used by `Send.Authorize`, called after `Prepare` in `RequestService.Send` and the runner) loads, refreshes within `RefreshWindow` (30 s, under a per-owner lock in the shared `pipeline.OAuth2`, `Core.oauth`), or fetches for client credentials/password; never a browser flow; failures are `*pipeline.AuthError` → `httpexec.KindAuth` ("auth"; `Locked` → `SecretsLocked`). The token becomes bearer/query auth via `auth.TokenAuth` and is masked as `[secret:oauth2AccessToken]` (`auth.TokenName`); `SendSecrets` includes the stored token (examples scan). `auth.Apply` refuses an untranslated oauth2 auth (`ErrOAuth2Token`); `auth.Materialize` writes `{{oauth2AccessToken}}`; `PrepareCode` puts the real token in only when resolving and revealing. Token endpoints use `Executor.HTTPClient()` (app transports, no jar/hops). Deleting a request/folder/collection deletes its subtree's tokens (`Session.DeleteRequest/DeleteFolder/DeleteCollection`, index-driven); duplicates get none; `PruneSecrets` keeps a token while its owner uses OAuth 2.0. `AuthService` (thin; `NewAuthService(core, AppControl)`): `StartOAuth2(ctx, flowId, ownerId, parentId, auth)` (browser via `AppControl.OpenURL`, `oauth2:flow` event with the URL, 5 min timeout, `CancelOAuth2(flowId)`), `OAuth2TokenStatus` (never values; `locked`), `RevealOAuth2Token` (explicit only), `RefreshOAuth2`, `ClearOAuth2Token`. The loopback server (`oauth2.Listen`) binds 127.0.0.1 only (plus ::1 for `localhost`), is single-use, checks `state` in constant time and serves a self-contained page (no external assets, CSP). Tests: `oauth2test.New` + `oauth2test.Browse` (follows the redirect, posts an implicit fragment); `e2e_oauth2_test.go` uses a `browserApp` whose `OpenURL` browses.
- **Codegen:** golden files per language (`go test ./internal/core/codegen -update` regenerates them); `PAKPOS_CODEGEN_SYNTAX=1` compiles every case with real toolchains (CI runs it on Linux). Secrets stay `{{name}}` (`vars.KeepSecrets`) unless revealed; revealed code lives only in the code dialog's state. Shared helpers: `auth.Materialize`, `urlx.SendURL`, `curl.SuggestName`.
- **Examples** (`fsstore/examples.go`): a `<request stem>.examples.yaml` sidecar follows its request on rename, move, duplicate (new ids) and delete; a broken or foreign sidecar is listed in Problems and never overwritten. `ExampleService.Save` scans for echoed secrets (`Session.ExampleSecrets`: values plus base64/URL-encoded forms and Basic credentials) before writing. Services return capitalised user messages through `userError` (staticcheck refuses capitalised `errors.New`).
- **Scripts** (`core/script`, `pipeline/scripts.go`):
  - `model.Scripts{PreRequest, Test}` lives on requests, `_folder.yaml` and `_collection.yaml` (`scripts: {preRequest: |, test: |}`, literal block scalars via `Scripts.MarshalYAML`, omitted when empty). Non-empty scripts are a v3-only write (`upgradeForRequestLocked`, `SaveFolder`, `SaveCollection`). `FolderSettings.Scripts`/`CollectionSettings.Scripts` are pointers: nil keeps the saved scripts. `inherit.Level.Scripts` carries each level's scripts.
  - `RequestService.Send` stays thin: `Session.NewSend` (or `NewSendWithoutWorkspace`) → `Send.PreRequest` (collection → folders → request; stops on the first error or `skipRequest`) → `Send.Prepare` → `Execute` → `Send.Test` (same order; errors become failed `Script error` tests). A pre-request error is `KindScript` and is recorded; a skip sets `SendResult.skipped` and records nothing. History keeps the request as written (no script changes).
  - `script.Run` gets a fresh goja runtime per run; the timeout is `settings.ScriptTimeoutMs` (1–60 s). The JS side (`prelude.js`, `expect.js`) talks to Go only through the host object passed to the prelude closure; request/response cross as JSON. Keep `require`/timers/`fetch` throwing an explanatory error. Console caps are per send (`script.Budget`).
  - **Overlay**: `pipeline.Overlay` (scope id → name → value or unset), one per opened workspace in `Core` (`overlayFor(wsID)`; new on every open, dropped on close). `Core.session` passes it with `WithOverlay`, and `BuildScopes` lays it over file values, so Preview/VisibleVariables (`PreviewVariable.overlay`: "set"/"new"), code generation and secret scans see it. Scripts write: `pm.variables` → the send's local scope; other scopes → the overlay, or the secret store (through the session, so the index records it) when the target is `secret: true`. Never write overlay values to SQLite or files except through `EnvService.PersistOverlay` (which uses `SaveVariables`); `ResetOverlay` drops them (key "" = whole scope); `OverlayValues` lists them (secret values never returned).
  - **Masking**: `Send.Secrets()` = `SendSecrets` + values scripts wrote to secrets (+ encoded forms). Console text, test names/errors, the script error message and hops are masked before leaving `pipeline`. Never return or emit unmasked script output.
  - **Event** `script:console` (`EventScriptConsole`, `ScriptConsoleEvent{sendId, entries}`), one per script run that logged, already masked; frontend `api.onScriptConsole`.
  - Code generation and previews never run scripts.
  - A pre-request error also sets `SendResult.ScriptError {source, line, column}` (nil otherwise) so the UI can open that level's script.
- **Collection runner** (`internal/runner`, `service/runner.go`):
  - `runner.New(Config)` checks the config (iterations 1–10000 or 0 = one per data row, delay 0–60000 ms, a data file with rows matching the iterations) and resolves the order from `ws.Tree()` (depth-first, tree order, optional `RequestIDs` subset); errors are `*runner.ConfigError`/`*runner.DataError` with user sentences (`userErr` in the service). `Runner.Run(ctx, Sink)` returns a `runner.Report`; `runner.Run` does both. Requests are read once when the run starts.
  - Each send is a `pipeline.Send` (`Session.NewSend`), so scripts, overlay and masking match a single send. The iteration's local scope carries over between sends (`ScriptOptions.Local` ← `Send.Local()`), seeded from the data row. "Keep variable values" off → `Session.Isolated()` (private overlay copy). History only with `RecordHistory` (`Config.Record` → `Core.recordHistory`); otherwise a spilled body file is removed. Saved responses are text only, masked, `MaxSavedBody`/`MaxSavedBodies`.
  - `setNextRequest`: first request with that name, else that id; `null` ends the iteration; more than `MaxJumps` (1000) per iteration or an unknown target ends the run with `OutcomeError`. Tests inject `Config.Sleep` (and `RunnerService.sleep`) instead of sleeping.
  - `RunnerService` (thin): `Start(config) → runId` (runs in a goroutine with its own context; one active run per workspace, `MsgRunActive`; the run keeps its start workspace), `Cancel`, `Active`, `List` (`RunListItem` with totals), `Get` (`runner.Report`), `Delete`, `Export(runId, "json"|"html")` through `Dialogs.SaveFile`, `PickDataFile`, `PreviewData(path)`. Progress is the typed event `runner:progress` (`EventRunnerProgress`, `RunnerProgressEvent{runId, workspaceId, event}`); the `finished` event is emitted only after the run is stored.
  - Storage: `0006_runs.sql`, `sqlite/runs.go` (`AddRun(rec, keep)` prunes to `sqlite.MaxRuns` = 20 per workspace, `ListRuns`, `GetRun`, `DeleteRun`); the store keeps the report as JSON and doesn't import the runner. Only the data file's name is stored.
  - Reports: `runner/report` `JSON`/`HTML` (`html/template`, embedded CSS with `prefers-color-scheme`, no JS or external assets). Golden files: `go test ./internal/runner/report -update`. Bump `report.Version` on a non-additive schema change.
  - e2e: `service/e2e_runner_test.go` (login → token → authenticated chain over CSV rows, stored run, JSON/HTML exports and the database scanned for secret values, cancel, one run per workspace).
- `internal/service/e2e_test.go` is the end-to-end check of the Go side (real stores, real HTTP). Extend it when you add a user-visible backend flow.
- Workspace writes go through `fsstore.Workspace` methods. They write atomically and mark the path as the app's own write, so the watcher does not echo it back as an external change.
  - Folders are directories with `_folder.yaml` `{id, name, seq, auth, headers}`; `*.examples.yaml` files are skipped by the request loader. A folder's path is always derived from the parent ids (`dirLocked`), never cached; deleting a subtree calls `markTree` before `RemoveAll`.
  - Moves keep ids and re-slug against the target; moving a folder into its own subtree is `ErrInvalidMove`. `InheritChain(id)` returns levels collection first.
  - The manifest stays at v1 until the first v2-only write (folders, environments, globals, examples, collection secrets): those writes call `upgradeManifestLocked(VersionV2)`. `FormatVersion` (3) is the newest version this build reads and what new workspaces get; a v3-only write (Tier 3 scripts, new auth, request settings) calls `upgradeManifestLocked(FormatVersion)`. `Open` refuses a newer manifest with `ErrUnsupported`; `WorkspaceService.Open` turns it into `MsgNewerWorkspace`, which the frontend matches on "newer version of Pakpos". Bump `FormatVersion` whenever a format change would be lost by an older build that saves.
- App data lives in `os.UserConfigDir()/pakpos`: `pakpos.db`, `bodies/`, `tmp/`. Set `XDG_CONFIG_HOME` to a temp dir when smoke-running the app, so you don't touch real data.

## Frontend conventions

- Import from `src` using the `@/` alias.
- **`src/components/ui/` holds vendored shadcn code**, added with `npx shadcn@latest add <name>`. It is excluded from lint, Prettier and coverage. Keep edits there minimal.
  - Known edit: `sonner.tsx` uses `useResolvedTheme` instead of `next-themes`.
  - These components import `cn` from the npm package `cn` (shadcn's official one). App code imports it from `@/lib/utils`.
- **Colors come only from theme tokens in `src/index.css`.** Do not hardcode hex values in components.
  - Use `bg-background`, `text-muted-foreground`, `bg-sidebar`, `text-primary`, and so on.
  - HTTP method colors: `text-method-get|post|put|patch|delete|other`, applied with `methodTextClass()` from `@/lib/http`.
  - Light and dark themes are both required. Dark mode is the `.dark` class on `<html>`, applied by `useResolvedTheme`.
- **Fonts:**
  - IBM Plex Sans (`font-sans`) for the UI.
  - JetBrains Mono (`font-mono`) only for content that is code: URLs, bodies, headers, method badges. Do not use it for decorative labels.
- **Design voice:**
  - It's a dense, quiet tool UI; the URL bar and method colors are the only accents.
  - No gradients or decorative shadows.
  - Write copy in sentence case, plain and active. Name buttons by what they do ("Send", "Save request").
  - Empty states tell the user what to do next. Error messages say what went wrong and how to fix it.
- **Accessibility:**
  - Every icon-only control needs an `aria-label` (and a tooltip).
  - Keep focus states visible.
  - Respect `prefers-reduced-motion`, which `index.css` already handles globally.
- Toasts that must not cover a dialog use `dismissOnDialog(id)` (`lib/dialogToasts.ts`).
- Component state goes in Zustand stores (`src/stores`). Persist only UI preferences to `localStorage`. Real data comes from Go services.
  - `stores/tabs.ts` is the exception: it keeps open tabs and drafts in localStorage as a convenience (never results). Storage access is wrapped so it never throws.
- **Tabs:** request tabs have `parentId` (collection or folder) and `workspaceId`. `Tab.doc` is set for non-request tabs (environment, globals, collection or folder settings, runner): check `tab.doc` before using request fields; `saveTab` routes doc tabs to `saveDocTab` (a no-op for runner tabs). A runner tab (`doc.kind = "runner"`, `doc.runner: RunnerSettings`, draft always null, one per target via `openRunner`/`openRunnerFor`) persists only its configuration (`excludedIds`, environment, iterations, delay, data file path, options); `syncContainerTabs` keeps its name and closes it when the target goes. Renaming from a doc tab (`DocEditor` `renameDocTarget`) goes through the environments or workspace store actions, and the tab name follows the tree (`syncContainerTabs`).
- **Tool tabs** (`docs/PLAN-TOOLS.md`): `Tab.tool: {id, state} | null` beside `doc`; use `isRequestTab(tab)` (neither doc nor tool) before reading request fields. Tools come from `features/tools/registry.ts` (`ToolDef`: label, description, icon, keywords, `persist`, lazy `component` loaded via `dialogChunks`, `initialState`/`withInput`/`restore`); the Tools sidebar view, palette "Open <tool>" actions (group "Tools"), tab title and icon all read it. `openTool(id, input?)` keeps one tab per tool (input replaces the open tab's input); `updateToolState(tabId, fn)`. Tool tabs have no workspace or parent (workspace switches and `syncTabs` skip them), are never dirty and have no Save. Their state reaches localStorage only with `persist: true` (never for JWT), through the def's `serialize` when it has one (the JSON tool drops inputs over 100 KB). Tool inputs resolve `{{vars}}` in TS (`features/tools/resolveVars.ts`) over `useVariableScope`'s visible variables (globals + selected environment); secrets resolve only after an explicit Reveal (`EnvService.RevealSecret`), kept in the tab's state. JWT decoding is `features/tools/jwt/jwt.ts` (pure); the token editor uses the lazy `jwt` editor language. The JSON tool (`features/tools/json/`): `json.ts` is an iterative parser that keeps numbers and strings as written, with positioned errors (line/column) that `errorMark.ts` marks in the input through `CodeEditor`'s `extensions` prop; inputs from 200 KB are processed after a 250 ms pause; the response body menu's "Open in JSON tool" passes the selection or the whole body. The URL tool (`features/tools/url/`): `url.ts` encodes/decodes in component, form and full-URL modes (full keeps reserved characters, existing %XX escapes and `{{var}}` references; its decode leaves reserved characters escaped, like `decodeURI`), never throws on bad escapes (errors carry an offset), and `parseUrl` reads scheme/host/port/path/query/fragment with `lib/urlx` so the query matches the Params table; "Open as request" is `openDraft(setUrl(emptyRequest(), url))`. `features/tools/useSettled.ts` holds the shared 10 MiB limit and the large-input debounce.
- **Remembered UI state** (`stores/uiState.ts`, Go-backed, loaded in `main.tsx` before the first render, writes debounced per key): resizable panel groups spread `usePanelLayout(id)`; tables with a key/value split use `useColumnSplit(table, default)` (CSS vars `--col-a`/`--col-b` in the grid template so memo rows don't re-render), mark the two header cells with `SPLIT_A`/`SPLIT_B` and put a `<ColumnResizer>` in the first. Key/value tables share the `keyValue` split.
- **Stores** (besides tabs, workspace, history, settings): `cookies.ts` (the cookie manager dialog and the jar's list; `openManager(domain)` from the palette's "Manage cookies" and the response Cookies tab), `update.ts` (update check/install; the skipped version is a localStorage preference), `environments.ts` (bumps `version` on every change so previews re-resolve), `secrets.ts` (call `ensureReady()` before any secret-store call; it opens the set-password or unlock dialog), `tree.ts` (expand state; use `revealInTree`, never focus rows directly), `examples.ts` (+ `useExamplesSync`, reloaded after every tree reload), `palette.ts`, `codeDialogs.ts`, `console.ts` (the console drawer: `open`, groups of lines per send, `unread`; `begin`/`finish` are called by `sendTab`, `append` by `useConsoleSync` from `script:console` events; `finish` replaces a group's live lines with `SendResult.console` so nothing shows twice and ignores late events; `addRunSend` adds a runner send's lines in one go with a `context` ("Run API · Iteration 2") shown in the header; capped at 2000 lines; in memory only, never persisted), `runner.ts` (runs by id, live from `runner:progress` (subscribed on the first `start`) or loaded with `openPast`; `shown[targetId]` is the run a runner tab shows; `past` is `RunnerService.List`; never persisted), `oauth2.ts` (token status, running flow (with the `oauth2:flow` URL) and last error per owner id; every action calls `ensureReady()` first; "Cancelled." is not shown as an error; never holds token values).
- **Palette commands** go in `features/palette/actions.ts` (id, label, group, shortcut, `enabled(ctx)`, `run(ctx)`). `useShortcuts` listens in the capture phase and ignores everything but Mod+K while the palette is open. Taken shortcuts: Mod+K, Mod+I (variable info), Mod+J (toggle console), Mod+Shift+C (generate code), Mod+Enter, Mod+S, Mod+T, Mod+W, Mod+,. - **Response Tests tab** (`features/response/TestsView.tsx`, `tests.ts`): "Tests passed/total" (`text-status-ok`/`text-status-client`), filter All/Passed/Failed, each test links to its script. A skipped send and a `script` error (with "Open the pre-request script…" from `scriptError`) replace the response.

Multi-line text that can hold `{{vars}}` (bodies, the headers' "Edit as text" view) is a `<CodeEditor variables={useVarScope()}>`. Any single-line field that can hold `{{vars}}` is a `VarInput` (static text, a CodeMirror editor only while focused); name cells stay plain inputs. Table rows stay `memo` components with stable handlers. Colours: `--syntax-var-*` tokens and the `.var-*` classes.
- **Code editors use `<CodeEditor>`** (`src/components/editor`), not CodeMirror directly.
  - It's created once per mount. Language and read-only changes go through compartments.
  - Value changes from props are tagged with the `External` annotation so they aren't echoed back to `onChange`. Without it, editing the params table would re-parse the URL and reorder rows.
  - Pass `key={tabId}` so each request gets its own undo history.

Keep `.cm-line` backgrounds (active line, `{{var}}` marks) translucent: the selection is drawn beneath them.
  - Its colors come from the `--syntax-*` and `--editor-*` tokens in `index.css`.
  - Props worth knowing: `variables` (decided at mount), `autoFocus`/`initialCursor`, `onBlur`, `onPaste(text) → handled` (the URL bar's cURL paste).

Rarely opened dialogs (settings, code, import cURL, palette, cookie manager) and the Scripts tab, console drawer and runner tab are `React.lazy` chunks mounted on first open and preloaded when the app is idle (`features/shell/LazyDialogs.tsx`; `schedulePreload` in `dialogChunks.ts`, skipped under Vitest).

Send error kind `auth` has copy in `features/response/format.ts`.

- **New code needs at least 80% coverage, for both Go and the frontend.** CI-style gates are enforced by `wails3 task coverage`; the thresholds are in `vite.config.ts` and `scripts/go-coverage.sh`.
- Use Vitest with jsdom and React Testing Library with `user-event`. Query by role and accessible name, not by class or test ID.

- The Wails Vite plugin is disabled under Vitest (`process.env.VITEST`), because it requires generated bindings.
- Mock Wails bindings in frontend tests. Never call real Go services from Vitest.

## Gotchas

- `frontend/bindings` only exists after `wails3 build`, `wails3 dev` or `wails3 generate bindings`. A plain `vite build` fails without it.
- `go vet ./...` at the root fails until `frontend/dist` exists, because of the `//go:embed`. Lint tasks run `go vet ./internal/...`.
- Text files are checked out with LF everywhere (`.gitattributes`); golden files and fixtures rely on it on Windows.
- npm prints `Unknown project config "minimum-release-age"`. This comes from `frontend/.npmrc` (a supply-chain guard for pnpm/bun) and is harmless.
- `@wailsio/runtime` is pinned to exactly `3.0.0` to match the Go module. Upgrade both together.
- yaml.v3 panics, rather than returning an error, on values it can't encode; `fsstore.marshalYAML` recovers from this.
- fsnotify drops a folder's watch when the folder is renamed. `fsstore.Watcher` re-syncs its watches on rename/remove events, and the workspace adds watches synchronously for folders it creates. Keep both.
- `RequestService.Send` takes a `context.Context` first; Wails passes it in and hides it from TS. Network failures are returned in `SendResult.Error`, not as Go errors.
- An input that mounts while a Radix menu is open (e.g. "Rename" from a context menu) loses `autoFocus` to the menu's focus trap. Focus it on the next tick, as `InlineRename` does.
- `fsstore.Open` errors contain "not a pakpos workspace" and `Create` errors contain "a workspace already exists here"; the frontend matches on these strings to offer the right next step.
- Tailwind's `sr-only` is `position: absolute`, so inside a CSS grid it drops out of the column flow. Wrap screen-reader-only header text in a normal grid cell: `<span role="columnheader"><span className="sr-only">…</span></span>`.
- An input that mounts inside a just-opened dialog or menu, or a row revealed from the palette, gets focus on the next tick; don't move focus synchronously after opening one.
- To screenshot the UI with fake data use `scripts/screenshot.mjs` (header comment has the steps): build the frontend (needs `frontend/bindings`), run `npx vite preview --port 4173` in `frontend/`, then `node scripts/screenshot.mjs --out <tmp dir> --theme both [--scenario file.mjs]`. It routes `**/wails/runtime*` (body `{object, method, args: {methodID, args}}`) and answers by method ID from the bindings; a scenario module exports `handlers` (`"EnvService.List": () => […]`, merged over the defaults) and `run({page, shot, theme})`. Unhandled methods are printed. `playwright` is a frontend devDependency; get a browser once with `npx playwright install chromium` (or set `PAKPOS_CHROMIUM`).
- **Windows is stricter than Linux/macOS; CI is its first test.** Rename or delete a directory only after `ws.unwatchDir(dir)` (the watcher's open handle makes it fail with "Access is denied"), then `watchDir` the new path. Don't rely on `chmod` to make writes fail (skip such tests on Windows). Never call fsnotify `Add` from the watcher's event loop. Check with `GOOS=windows go vet ./internal/...`, but only CI proves behavior.
- The Linux webview is WebKitGTK. Avoid bleeding-edge CSS and check rendering on Linux.

## Build, packaging and release

- **Releases use CalVer `vYY.MM.MICRO`** (e.g. `v26.11.1`; MICRO restarts at 1 each month; pre-releases `v26.11.2-rc.1`). The setup mirrors the Lontar (dbedit) project; keep them in sync. `tools/calver` validates tags; the release workflow fails on any other format.
- `VERSION` in the root Taskfile comes from `PAKPOS_VERSION` or `git describe --tags --always --dirty` (untagged → `0.0.0-dev+<hash>`); `VERSION_NUM` is its `X.Y.Z` core. `VERSION_LDFLAGS` (`-X pakpos/internal/buildinfo.Version=… -X …Commit=…`) goes into every platform's `BUILD_FLAGS`, and `tools/stamp` writes the version into the macOS Info.plist and the Windows info.json copy (`info.stamped.json`, git-ignored). Keep those hooks if you edit `build/<os>/Taskfile.yml`. `build/config.yml`'s `version` is only a baseline (0.0.0).
- `tools/` is a separate Go module: root `go test ./...` and golangci-lint don't cover it. Run `go -C tools test ./...` (part of `wails3 task test` and `coverage`).
- The Windows installer is per-user by default (`INSTALL_SCOPE=machine` for Program Files) and lands in `bin/pakpos-<arch>-installer.exe`. `SKIP_BUILD=true` reuses an existing (signed) `bin/pakpos.exe`.
- Signing scripts: `build/windows/sign.ps1`, `build/darwin/sign-notarize.sh` + `entitlements.plist`. They only run in the release workflow when the secrets exist.
- **In-app updates** (`internal/update`, ported from Lontar; keep the two in step): `UpdateService` checks GitHub's latest stable release of `update.Repo`, and installs only when `SHA256SUMS.sig` (ed25519, `UPDATE_SIGNING_KEY` in CI via `tools/updatesign`) verifies against the compiled-in `update.PublicKey` and the asset's SHA-256 matches. It replaces the AppImage, the Windows exe (from the portable zip) or the macOS `.app` (from the dmg); `.deb`/`.rpm` and dev builds only get the release page. `update.AssetName` must match the file names in `release.yml`. The frontend (`stores/update.ts`, `features/update/`) checks at startup and daily while the `checkForUpdates` setting is on; installing always needs a click. The app's `OpenURL`/`Quit` go through `service.AppControl`.
- `wails3 task common:update:build-assets` regenerates Info.plist, Windows info.json/NSIS/manifest, `build/linux/desktop` and **`build/linux/nfpm/nfpm.yaml`** from `build/config.yml`. It overwrites our edits (nfpm: `${PAKPOS_PKG_VERSION}`, Apache-2.0, LICENSE/NOTICE, icons; Info.plist hand-added keys; NSIS `project.nsi` version defines), deletes `build/darwin/entitlements.plist`, and re-adds `build/ios/`.
